
- **Primary Key** automatically creates a unique index on that column(s).
- **Foreign Key** enforces referential integrity but may not automatically index the foreign key column (in many engines, you should add an index on foreign keys for faster JOINs).

```sql
-- Add an index on employees.department_id for faster joins/filters
CREATE INDEX idx_emp_department
ON employees (department_id);

-- Composite index example:
-- Suppose queries often filter WHERE department_id = X AND salary > Y
CREATE INDEX idx_emp_dept_salary
ON employees (department_id, salary);

```

- **Index types** (depending on engine):
    - **B-tree** (default for equality/range lookups)
    - **Hash** (MySQL only, some cases, not for range)
    - **GIN/GiST** (PostgreSQL for JSON/text search, arrays)

- **When to index**:
    - Columns in `WHERE`, `JOIN ON`, `ORDER BY`, `GROUP BY` frequently.
    - Avoid over-indexing: each index slows down `INSERT`/`UPDATE`/`DELETE`.

- **EXPLAIN / EXPLAIN ANALYZE**: Always discuss how to inspect query plans. Example (PostgreSQL):

```sql
EXPLAIN ANALYZE
SELECT e.first_name, e.last_name, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id
WHERE e.salary > 80000;

```
The output shows whether it used an index scan or a sequential scan, estimated vs actual row counts, etc. Interviewers love discussing how to interpret `EXPLAIN` output.
