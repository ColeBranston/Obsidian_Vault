
Window functions compute values over partitions without collapsing rows. Common when you want ranks, cumulative sums, moving averages, etc.

Assume a table `sales (sale_id, product_id, sale_date, amount, region)`.

```sql
-- 10.1. ROW_NUMBER() example: rank sales per region by amount
SELECT
  sale_id,
  product_id,
  region,
  amount,
  ROW_NUMBER() OVER (
    PARTITION BY region
    ORDER BY amount DESC
  ) AS sale_rank
FROM sales;

-- 10.2. RANK() vs DENSE_RANK()
-- RANK() leaves gaps if ties; DENSE_RANK() does not.
SELECT
  sale_id,
  product_id,
  region,
  amount,
  RANK() OVER (PARTITION BY region ORDER BY amount DESC)      AS rnk,
  DENSE_RANK() OVER (PARTITION BY region ORDER BY amount DESC) AS dense_rnk
FROM sales;

-- 10.3. NTILE(): assign rows to buckets
SELECT
  sale_id,
  product_id,
  amount,
  NTILE(4) OVER (PARTITION BY region ORDER BY amount DESC) AS quartile
FROM sales;

-- 10.4. Cumulative SUM (running total) per product over time
SELECT
  sale_id,
  product_id,
  sale_date,
  amount,
  SUM(amount) OVER (
    PARTITION BY product_id
    ORDER BY sale_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM sales
ORDER BY product_id, sale_date;

-- 10.5. LAG/LEAD: compare to previous/next row
SELECT
  sale_id,
  product_id,
  sale_date,
  amount,
  LAG(amount, 1) OVER (PARTITION BY product_id ORDER BY sale_date)  AS prev_amount,
  LEAD(amount, 1) OVER (PARTITION BY product_id ORDER BY sale_date) AS next_amount
FROM sales;

```

- **OVER (PARTITION BY… ORDER BY…)** defines how rows are grouped (partitioned) and the order.
- Frames: default `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, but you can use `ROWS BETWEEN X PRECEDING AND Y FOLLOWING` for sliding windows.
- Use window functions when you need per-row computations based on other rows but still return all original rows.
