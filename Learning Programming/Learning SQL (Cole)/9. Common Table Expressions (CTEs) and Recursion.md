
### 9.1. Non-recursive CTE

Helps break complex queries into named subqueries.

```sql
WITH dept_salaries AS (
  SELECT department_id, AVG(salary) AS avg_salary
  FROM employees
  GROUP BY department_id
),
high_earners AS (
  SELECT e.employee_id, e.first_name, e.last_name, e.salary, ds.avg_salary
  FROM employees e
  JOIN dept_salaries ds ON e.department_id = ds.department_id
  WHERE e.salary > ds.avg_salary
)
SELECT *
FROM high_earners
ORDER BY salary DESC;

```
### 9.2. Recursive CTE (e.g., hierarchy or paths)

Generate hierarchical data or run cumulative computations.

```sql
-- Example: employee reporting hierarchy (assume each employee has manager_id)
CREATE TABLE employees_hier (
  employee_id   INT PRIMARY KEY,
  first_name    VARCHAR(50),
  last_name     VARCHAR(50),
  manager_id    INT REFERENCES employees_hier(employee_id)
);

-- Recursive CTE to get each employee’s chain up to the CEO (manager_id IS NULL)
WITH RECURSIVE management_chain AS (
  -- Anchor member: start with employees who report to no one (CEOs)
  SELECT
    employee_id,
    first_name,
    last_name,
    manager_id,
    0 AS level,
    ARRAY[employee_id] AS path       -- PostgreSQL array for path tracking
  FROM employees_hier
  WHERE manager_id IS NULL

  UNION ALL

  -- Recursive member: find direct reports
  SELECT
    e.employee_id,
    e.first_name,
    e.last_name,
    e.manager_id,
    mc.level + 1 AS level,
    mc.path || e.employee_id AS path
  FROM employees_hier e
  JOIN management_chain mc
    ON e.manager_id = mc.employee_id
)
SELECT * 
FROM management_chain
ORDER BY level, employee_id;

```
- Recursive CTEs must have an **anchor** and a **recursive** part; include `UNION ALL`.
- Useful for graph traversals, hierarchical data, factorial calculations, etc.
