
**1. Broadcast Variables**
- Used to efficiently share a large, read-only variable (e.g., a lookup table/dict) across all executors without sending it with every task.

- In PySpark:
```Python
lookup_dict = {"US": "United States", "CA": "Canada", "MX": "Mexico"}
broadcast_var = spark.sparkContext.broadcast(lookup_dict)

# In an RDD map:
rdd = sc.parallelize(["US", "CA", "MX"])
mapped = rdd.map(lambda code: broadcast_var.value.get(code, "Unknown"))
print(mapped.collect())
```
- In DataFrame API, you can also do:

```Python
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

bc_lookup = spark.sparkContext.broadcast(lookup_dict)
@udf(returnType=StringType())
def lookup_udf(code):
   return bc_lookup.value.get(code, "Unknown")

df.withColumn("country_name", lookup_udf(col("country_code"))).show()

```

**2. Accumulators**
- Write-only variables to aggregate counts or sums across executors (e.g., error counters).
- In PySpark:

```Python
acc = spark.sparkContext.accumulator(0)
rdd = sc.parallelize([1, 2, 0, 4, 0, 5])

def check_zero(x):
   if x == 0:
       acc.add(1)
   return x

_ = rdd.map(check_zero).collect()
print("Number of zeros:", acc.value)   # e.g., 2

```
**3. User-Defined Functions (UDFs)**

- Use UDFs when you need custom Python logic per row. However, Python UDFs serialize data to Python, run your code, then serialize results back—this is slower than built-in Spark functions.
- If possible, rewrite logic using built-in `pyspark.sql.functions` (e.g., `when`, `regexp_replace`, `concat_ws`, `expr`).
- PySpark also supports **Pandas UDFs** (vectorized), which are faster than row-by-row UDFs, but they still incur serialization overhead between JVM and Python processes.
- Example:

```Python
from pyspark.sql.functions import udf
from pyspark.sql.types import IntegerType

@udf(returnType=IntegerType())
def string_length(s):
    return len(s) if s else 0

df.withColumn("name_length", string_length(col("name"))).show()

```
