
1. **Explain Spark’s architecture (driver, executors, cluster manager).**
    - Describe how the driver builds the DAG and how executors run tasks in parallel.

2. **Difference between RDDs and DataFrames (pros/cons).**
    - RDD: low-level, untyped, no schema, user-controlled partitioning.
    - DataFrame: high-level, schema, Catalyst optimizations, better performance.

3. **What is lazy evaluation?**
    - Transformations are not executed until an action is called; allows global query optimization.

4. **Explain transformations vs actions. Give examples.**
    - Transformations: `map`, `filter`, `flatMap`, `join` (create new RDD/DataFrame).
    - Actions: `collect`, `count`, `show`, `write`.

5. **How does Spark handle data distribution & fault tolerance?**
    - Data is partitioned across executors.
    - Lineage DAG: if a partition is lost, Spark re-computes from parent RDDs (fault tolerance).

6. **What is a shuffle? Why is it expensive?**
    - When data must be re-distributed across partitions (e.g., `groupBy`, `reduceByKey`, `join`).
    - Shuffle writes data to disk, transfers over network, then reads back ⇒ I/O heavy.

7. **How do you optimize a slow job?**
    - Reduce shuffles (push filters/projections early).
    - Broadcast small tables for joins.
    - Adjust `spark.sql.shuffle.partitions` to match data size.
    - Cache frequently used intermediate DataFrames.
    - Use built-in functions instead of Python UDFs.

8. **Explain partitioning and coalesce vs repartition.**
    - `repartition(n)`: full shuffle to create `n` partitions.
    - `coalesce(n)`: narrow dependency, does not shuffle if reducing partition count (better if data is already balanced).

9. **What are broadcast variables and accumulators?**
    - Broadcast: read-only shared across executors (e.g., small lookup table).
    - Accumulator: write-only counters/aggregators (e.g., counting errors while mapping).

10. **When would you use a UDF and what are its downsides?**
	- Use UDF for custom row-by-row logic not expressible with built-ins.
	- Downside: serialization overhead, slower than built-in functions, breaks predicate pushdown/optimization.

11. **Explain how Spark SQL fits in.**
	- Spark SQL converts SQL queries into DataFrame logical plans; benefits from Catalyst.
	- You can mix DataFrame DSL and SQL seamlessly.

12. **How do you handle skewed data?**
	- Salting keys, repartitioning, using `groupByKey` vs `reduceByKey` differences, sampling to detect skew.

13. **How does caching work, and when would you use it?**
	- `df.cache()`: persists DataFrame in memory across executors to speed up repeated queries.
	- Use when you reuse the same intermediate DataFrame multiple times.

14. **Real-world scenario/whiteboard problem:**
	- E.g., “Given a massive log file of user clicks (user_id, timestamp, url), find the top 10 most visited URLs per country.”

	- Answer:
	    1. Read logs via DataFrame with schema.
	    2. Filter relevant timeframe.
	    3. Join with a country lookup (broadcast small dimension).
	    4. GroupBy (`country`, `url`), count.
	    5. Window function (row_number over partition by country order by count desc), filter top 10.
	    6. Write results out.

### Quick PySpark Code Snippet for “Top 10 URLs per Country” Example

```Python
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, count, row_number
from pyspark.sql.window import Window

spark = SparkSession.builder.appName("TopURLs").getOrCreate()

# 1. Read clicks (massive CSV/parquet): columns: user_id, timestamp, url, country_code
clicks = spark.read.parquet("s3a://logs/clicks/")

# 2. Read small dimension: country_code → country_name (broadcast)
countries = spark.read.csv("s3a://dims/countries.csv", header=True, inferSchema=True)
countries_broadcast = spark.sparkContext.broadcast(
    {row["country_code"]: row["country_name"] for row in countries.collect()}
)

from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

@udf(returnType=StringType())
def map_country(code):
    return countries_broadcast.value.get(code, "Unknown")

clicks_enriched = clicks.withColumn("country", map_country(col("country_code")))

# 3. Aggregate URL counts per country
url_counts = clicks_enriched.groupBy("country", "url").agg(count("*").alias("cnt"))

# 4. Use window to rank top 10 per country
window_spec = Window.partitionBy("country").orderBy(col("cnt").desc())
ranked = url_counts.withColumn("rank", row_number().over(window_spec))

top10 = ranked.filter(col("rank") <= 10)

top10.show(100)
spark.stop()

```

- This demonstrates reading data, broadcasting a small lookup, grouping, and using a window function to pick top 10 per group. Anticipate interviewers asking about the performance impact of collecting a small dimension (`countries.collect()`) and broadcasting it.
