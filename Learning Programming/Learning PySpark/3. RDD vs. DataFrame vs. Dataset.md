
**1. RDD (Resilient Distributed Dataset)**

- The original low-level API (since Spark 1.x)
- Immutable, partitioned collection of objects.
- Supports two kinds of operations:
	- Transformations (lazy) eg. `map()`, `filter()`, `flatMap()`, `recudeByKey()`
	- Actions (eager): eg. `collect()`, `count()`, `take()`, `saveAsTextFile()`
- No schema or type safety: each element is a plan Python object (eg. tuple, list, dict)

**2. DataFrame**

- Introduced in Spark 1.3 Formalized in Spark2.x
- Equivalent to a table in a relational database: rows with named columns and a schema.
- Underneath, a DataFrame is just an RDD of `Row` objects plus schema metadata.
- Exposes SQL-like APIs (`select`, `filter`, `groupBy`, `join`, etc.)
- Benefits
	- **Catalyst Optimizer** automatically rewrites queries for better performance.
- Supports reading/writing to Parquet, JSON, CSV, ORC, JDBC, etc. with schema inference or manual schema.

**3. Dataset (typed)**

- Introduced in Spark 1.6 and stabilized in Spark 2.x (Scala/Java only).
- In Python, DataFrames and Datasets are unified under the DataFrame API (RDD-like type checks are weaker).
- Scala/Java Datasets have compile-time type safety: Python DataFrames do not enforce types at compile time.

**In Interviews, people usually focus on DataFrames (PySpark's "df" API)** rather than raw RDDs. Be ready to explain why you'd prefer DataFrames (schema, performance, Catalyst) and when RDDs might still be necessary (fine-grained control, custom positioning logic, low-level transformations).
