
- If you reuse intermediate results multiple times, cache them to avoid recomputing:

```python
df2 = df.filter(col("status") == "active")
df2.cache()       # persists in memory (default level: MEMORY_AND_DISK)
df2.count()       # first action ⇒ compute & cache
df2.groupBy("region").agg(count("*")).show()   # reused from cache

```
**Persistence levels**:

- `MEMORY_ONLY`, `MEMORY_AND_DISK`, `DISK_ONLY`, `MEMORY_ONLY_SER` (serialized), etc.
- Choose based on available cluster memory and cost of recomputation vs storage.

**Memory tuning**:

- `executor.memoryFraction` and `executor.memoryStorageFraction` determine how much of an executor’s heap is reserved for execution vs storage (Spark manages these automatically in recent versions).
- If you see **OutOfMemoryError**:
	- Increase executor memory.
    - Decrease `spark.sql.shuffle.partitions` if too many small tasks.
    - Persist only what you need; unpersist when no longer needed (`df.unpersist()`).
