The language of **well-formed (balanced) parentheses** — e.g. (()()) is in, but (() and ())(() are not — is generated by the [[Context-free Grammar]]

> **S → (S) | SS | ε**

- **(S)** — wrap a balanced string in a matched pair of brackets
- **SS** — split into two balanced components side by side
- **ε** — the empty string

*Deriving (()()):* S ⇒ (S) ⇒ (SS) ⇒ ((S)(S)) ⇒ (()()) — no more variables, so stop.

| Task | Answer |
|---|---|
| Derive ()() | S ⇒ SS ⇒ (S)S ⇒ ()S ⇒ ()(S) ⇒ ()() |
| Derive (()) | S ⇒ (S) ⇒ ((S)) ⇒ (()) |
| )( | **out** — reading left to right, the first symbol closes a bracket never opened |
| (() | **out** — two opens, one close |
| ()()() | **in** — S ⇒ SS ⇒ SSS, then each S ⇒ (S) ⇒ () |

**The two failure modes.** A string is unbalanced in exactly two ways: some **prefix has more ) than (**, or the **totals are unequal**. The grammar can produce neither — every rule inserts ( and ) as a matched pair. Lecture 9's [[Pushdown Automaton|PDA]] for this language kills each failure mode with a stack.

**Why all three rules** — delete any one and the grammar breaks:
- Without **SS**: every derivable string is fully nested like ((())) — ()() becomes unreachable
- Without **ε**: no derivation can ever terminate — the language would be empty
- Without **(S)**: only ε remains

> [!note] Gateway to compiler theory
> The syntax of every programming language — matched braces, nested expressions, blocks — is specified as a CFG, and a **parser** is the algorithm that reconstructs the [[Derivation]] of your source file.
