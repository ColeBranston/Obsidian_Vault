The **incremental model** repeats a Requirements → Design → Build → Test → Implement cycle per increment, layering each new increment on top of a shared **kernel**.

[[Waterfall Model|Waterfall]] and incremental models work best when the problem is well-defined, requirements can be clearly elicited, and technical feasibility is understood. In many real projects, though, it's hard to pin down exact requirements up front — or the technical issues aren't yet clear.
